# Cross-Symbol Validation — отчёт

**Метод:** идентичный OOS-анализ (последние 30% из 24 мес, 1h) на 5 символах.
Пайплайн: precompute с funding в контексте (без look-ahead) → фильтры
min_score=30, min_families=3 → портфельная симуляция с издержками
(taker 0.05%/сторона, slippage 2 б.п., funding).
**Данные:** 5 независимых синтетических серий (Binance из среды недоступен) —
**отрицательный контроль**: серии не содержат edge, поэтому полученная
межсимвольная дисперсия = эталон чистого шума для интерпретации будущих
реальных прогонов. Скрипт: `backend/scripts/cross_symbol_validation.py`.

| Метрика | Среднее | Std | Диапазон |
|---|---|---|---|
| Profit Factor | 0.943 | **0.080** | 0.819 … 1.037 |

Символов с положительным expectancy: **1 из 5**.

## Интерпретация (отрицательный контроль)

1. **Агрегат сошёлся к теории.** Exp = −0.029R при нулевом истинном edge —
   это почти точно средняя стоимость издержек на сделку. Система честно
   не находит преимущество там, где его нет; WR ≈ 50% подтверждает.
2. **Эталон шума.** При ~130 OOS-сделках на символ чистый шум даёт разброс
   PF ±0.08–0.11 и expectancy ±0.04R между символами. «ETH +0.016 при
   BTC −0.09» — случайный порядок: один из пяти символов оказывается
   «прибыльным» просто по комбинаторике выборки.
3. **Следствие для реальных данных** (критерии «работает на рынке в целом»,
   а не на одном символе):
   - агрегированный expectancy > 0 и бутстреп p < 0.05 на объединённых сделках;
   - ≥ 4 из 5 символов с expectancy > 0;
   - межсимвольный std expectancy сопоставим с шумовым эталоном (~0.04R
     при n≈130; масштабируется как 1/√n) — большая дисперсия означает
     режимную/символьную подгонку;
   - результат лучшего символа НЕ должен использоваться как «вердикт»:
     если только BTC проходит, а остальные на уровне шума — это
     BTC-специфическая подгонка, не рыночное преимущество.
